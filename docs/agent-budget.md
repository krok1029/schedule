# Agent 每週預算

狀態：監看式帳本已建立，自動執行器與硬性限額尚未接入。更新：2026-09-27。

## 已設定的政策

- Schedule 每個帳戶週用量週期，最多使用**該週總上限的 30%（30 個百分點）**。不是剩餘額度的 30%，也不是每張卡各分配 30%。
- 本專案的規劃、實作、測試分析、審查、子 agent 與重試共用同一筆預算；不因開新任務或換模型重新分配。
- 週期依帳戶用量來源的重設時間，不能任意當成每週一。未用完不累積到下週。
- 以 28 個百分點作為停止開新輪次的保守門檻，留下 2 個百分點處理收尾與讀值誤差；30% 是使用者上限，28% 是本次採用的操作緩衝。
- 同時遵守帳戶剩餘額度與其他短週期限額；不購買 credits、不切換付費 API，也不自行使用重設額度來增加本週預算。
- 每批 1 張任務、最長 60 分鐘、同一失敗最多 3 次有假設的修正；靠近門檻時需縮短批次，不能等 60 分鐘才檢查。

機器可讀政策在[agent-budget.json](../config/agent-budget.json)。這是本專案自訂設定，**不是 Codex 內建設定檔，也還沒有執行器載入它**。

## 能取得什麼數據

目前可讀帳戶級用量比例、週期長度與重設時間。應優先按 `limitId` 使用多額度視圖，依 `windowDurationMins` 識別週窗口，不能假定週用量一定在 primary 或 secondary。相同週期的 `usedPercent` 差額以百分點計算。[官方用量欄位](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)

Codex 用量會在帳戶內共用，不能把它解讀成單一專案消耗；週比例也沒有可直接套用的固定 token 換算。因此本政策不填虛構 token_budget。[官方用量說明](https://learn.chatgpt.com/docs/pricing)

本輪第一次讀取時，帳戶週用量是已使用 58%、剩餘 42%。這只是一個當時快照，**不是本專案先前用量、不是正式執行基線，也不是將 42% 再乘 30%**。首次開始受預算管理的執行前必須取得新讀值；既往無法歸屬的用量不得假裝已精確追溯。

## 保守記帳方式

1. 第一輪記錄額度識別、週期重設時間、開始讀值與任務 ID；各輪開始前讀取剩餘預算。
2. 每個可控小步、審查前後、重試前後與批次結束重新讀取。依資料庫式單一帳本累計，不能由每個 agent 各記一份重複差額。
3. 同一窗口內，執行區間的帳戶正差額全數記入專案。若其他專案同時消耗，暫時保守計入，不自行扣除猜測的比例。
4. 不執行本專案的間隔不收取該間隔增量；未完成區間從最後有效讀值恢復，避免 agent 中斷後漏算。讀值延遲或歸屬不明時保留「未結算」，不能顯示精確剩餘。
5. 換週時先結算舊窗口、建立新窗口。跨重設的未結算執行、額度識別改變、讀值異常下降或資料缺失時停止自動開始下一輪，先核對紀錄，不以負差額回補預算。
6. 若平台新增多個獨立週額度，暫停自動選模型跨額度執行，先建立共同計量方式；不能每個額度都默認再獲得 30%。

帳本至少保存：週期 ID、limitId、開始／結束讀值、區間是否已結算、保守扣帳百分點、累計、任務／執行 ID、停止原因。不得保存帳戶密鑰或私人內容。

## 停止與執行狀態

執行前可用上限取「專案剩餘預算」與「帳戶實際可用額度」較小者，並保留緩衝。保守扣帳達 28 個百分點時不開新輪次，只做必要保存；到達或超出 30 時停止工作並報告，不能以尚有帳戶額度為由繼續。

這種帳戶讀值比較是**保守估算**：其他專案混用、比例精度、更新延遲與單輪不可中斷的消耗，都可能使它無法嚴格卡在 30%。讀值看似未增加也不代表免費。執行器尚未建立，不能宣稱硬性上限已啟用。

M0.5 先以有人監看的小批次試跑，驗證用量讀取、紀錄、預警與停止。若執行平台無法限制或及時中斷單輪，就維持監看模式，不啟動無人值守長任務。此文件沒有建立自動排程，週期重設也不會自行啟動工作。

## 已實作的監看式帳本

`pnpm budget:record <snapshot.json>` 由操作中的 agent 先讀可信帳戶用量來源，再將最少欄位寫入快照。工具本身不會查詢帳戶，也無法攔截模型呼叫。不可將缺漏讀值改成零。

```json
{
  "limitId": "codex",
  "windowDurationMins": 10080,
  "resetsAt": 1791071949,
  "usedPercent": 64,
  "action": "start",
  "taskId": "SETUP-001",
  "observedAt": "以實際讀取時間填入"
}
```

範例讀值不可當成下一次真實用量；SETUP-001 本批起點實際為 64%。`start` 開始區間，`checkpoint` 中途結算，`end` 結束區間；已結束區間至下一次 start 的閒置差額不扣帳。未結束區間恢復後繼續保守扣帳。

帳本位於 `.agent/weekly-usage.json`（不進版本控制），暫時只允許一個操作者順序寫入；沒有並行鎖、跨電腦合併或自動換週能力，不能多 agent 同時操作，也不能清空帳本來重置額度。換週或讀值異常需先保留並核對舊帳本。

累計達 28 個百分點或帳戶剩餘 ≤2% 時回傳 stop；checkpoint／end 會保存記錄並回傳退出碼 2，start 會拒絕開新區間。到 30 個百分點必須停止。這是監看式操作信號，不是硬性用量閘門。
