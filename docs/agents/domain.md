# Domain Docs

採 single-context：根目錄 CONTEXT.md 保存詞彙，docs/adr/ 保存適用架構決策。

- 探索前先讀 CONTEXT.md 與觸及領域的 ADR，使用既定詞彙；文件不存在時繼續工作，在首次形成真實內容後才建立。
- CONTEXT.md 只放詞彙定義與需避免的混稱，不放實作、spec、檔案路徑或任務進度。
- 提問使用選項互動，建議答案排第一；不重問已確認的決策。新詞彙確認後即記錄。
- 只有難以逆轉、無上下文會令人疑惑，而且存在真實取捨時才建立 ADR；沿用 domain-modeling 的格式。
- 若發現程式與詞彙或 ADR 矛盾，先提出具體情境，不能默默改寫規則。
- 未來確有獨立領域時再建立 CONTEXT-MAP.md 與各領域文件；目前多平台不等於多個領域。
