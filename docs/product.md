# 產品功能與使用情境

狀態：完整功能願景。以下功能來自既有討論；原待決方向已依建議採用，細節見[決策紀錄](open-questions.md)；實作仍逐卡拆分。更新：2026-09-27。

## 產品要解決的問題

知道現在該做什麼，也知道上次做到哪裡。透過固定週課表安排生活，在每次執行後留下真實紀錄，再用每週回顧調整成能持續做到的節奏。

使用情境包含求職、英文學習、side project、運動、休閒與生活作息。使用者可自行新增項目，產品不把這些例子寫死。作息目標與目前實際狀態分開，不要求一開始就達標。

## 已確認的產品規則

- 七天各自安排，每週重複；晚起或錯過時段時，後面的課表不自動順延。
- 同一項目無論從哪個時段進入，都使用同一個項目頁面，顯示上次工作位置與下一步。
- 支援只改某一天，也支援修改固定週課表；衝突交由使用者選擇取消、改時間或保留重疊。
- 完成、部分完成、沒做、待補記、取消要能區分。未回應提醒保留待補記，不自動判定沒做。
- 實際投入時間手填；番茄鐘是輔助工具，不自動覆蓋手填紀錄。
- 目標可選填；沒有可衡量目標時，不硬算項目完成百分比。
- 一次性待辦可獨立存在；週期性待辦必須隸屬項目，每次完成狀態分開。
- 外部行事曆只讀取與顯示，不從本產品新增、修改或刪除外部行程。
- 手機、網頁與桌機要同步。明確不需要離線編輯。
- 圖譜聚焦項目與筆記頁面，支援手動連結、共同標籤、父子關係的顯示切換。
- 封存保留歷史；操作前顯示影響清單，預設保留未來安排與待辦，使用者可明確選擇取消／停止未來週期。

## 五個核心使用情境

### 開始時段

提醒目前該做英文 → 開啟英文項目 → 看見上次筆記位置與下一步 → 接續工作。另一個英文時段也進入同一項目。

### 結束與補記

收到結束提醒 → 選部分完成 → 手填 35 分鐘 → 留下「讀完第 3 章，下次做練習」。若沒有回應，保持待補記；之後可以補填。零分鐘必須是明確輸入，不能從缺漏資料推導。

### 臨時面試

新增當天下午面試 → 發現與英文重疊 → 使用者取消英文、調整時間或保留兩者 → 更新相應提醒 → 不影響下週英文安排。外部行事曆的面試只讀取顯示。

### 一次性搶票

建立不隸屬項目的待辦 → 設明天 12:00 → 設前一天、前一小時與前十分鐘提醒 → 在總覽查到 → 完成後狀態同步。完成後撤銷剩餘提醒，錯過提醒保留可查狀態。

### 每週回顧

查看預定與實際投入、待補記和常被跳過的時段 → 閱讀項目進展 → 草擬下一週課表 → 指定生效日期。不能用新課表重算過去原本排了什麼。

## 品質要求與範圍邊界

- 已確認成本限制：專案服務不付費；資料庫採 Supabase，開發採 Vite／Oxc 生態。免費配額不足時先調整方案，不自動升級。
- 完整功能願景保留；涉及付費商店會員、簽章或常駐服務的發布方式，需找到免費路徑才列入交付承諾。

- 同步失敗、通知未授權、健康資料不可用時，要顯示清楚狀態；缺資料不等於零。
- 重要寫入應能安全重試；同步衝突不應靜默覆蓋筆記。
- 日常記錄要簡短，詳細筆記與分析可在需要時展開。
- 目前未納入多人即時協作、團隊權限、付費訂閱、AI 自動排程或對話式助理。這些不是既有需求。
- 「像 Obsidian」指內容組織與連結能力，不代表承諾相容其外掛或直接同步 vault。
- 不提供離線編輯；斷線只讀已快取內容，保留當前未送出草稿，重連確認後再提交。
